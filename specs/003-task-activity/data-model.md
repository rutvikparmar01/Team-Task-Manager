# Phase 1 Data Model: Task Activity History

New entity, added alongside the existing entities documented in
`specs/001-team-task-management/data-model.md` (`Project`, `Task`, `TeamMember`, which this
feature does not modify).

## Activity

Represents a single, immutable historical record of something that happened to a task (spec
FR-001–FR-004, FR-011).

| Field | Type | Rules |
|---|---|---|
| `id` | string (Mongo ObjectId) | Generated by the database |
| `taskId` | string (ObjectId ref → Task) | Required; must reference an existing task |
| `category` | enum: `"TaskCreated" \| "AssigneeChanged" \| "StatusChanged" \| "PriorityChanged"` | Required; determines which of the fields below are populated |
| `fromStatus`, `toStatus` | enum: `"Todo" \| "In Progress" \| "Done"` | Present only when `category` is `"StatusChanged"` (FR-003) |
| `fromPriority`, `toPriority` | enum: `"Low" \| "Medium" \| "High"` | Present only when `category` is `"PriorityChanged"` (FR-004) |
| `assigneeId` | string (ObjectId ref → TeamMember) \| null | Present only when `category` is `"AssigneeChanged"`; `null` represents "unassigned" (FR-002) |
| `createdAt` | ISO date-time | Set on creation; the record is never updated afterward (FR-011) |

**Relationships**: Belongs to exactly one Task. Optionally references one TeamMember (only for
`AssigneeChanged` records).

**Index**: `{ taskId: 1, createdAt: -1 }` — see research.md item 5.

**Invariants** (enforced in `activityService`, not just by convention):
- No activity is ever updated or deleted after creation (FR-011) — the service exposes only
  `recordActivity` (insert) and `listActivitiesForTask` (read); there is no update/delete
  function to call, by construction, not just by omission from the API.
- A `StatusChanged` or `PriorityChanged` activity is only created when the value actually
  changes; a status/priority update that resolves to a no-op produces no activity (FR-003, FR-004
  edge cases).
- A single `PATCH /api/tasks/:taskId` request that changes multiple fields (e.g., status and
  priority together) produces one activity per field that actually changed, not one combined
  record (plan.md Constraints).

## Derived view: Task Activity History

Not a separate stored shape — `listActivitiesForTask(taskId)` returns `Activity[]` sorted
`createdAt` descending (FR-005), or an empty array when the task has none yet (frontend renders
the empty state for that case, per FR-008).
